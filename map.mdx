The Map draws your whole project from its newest snapshot. Each folder is an area, each function, class and type is a dot, and lines show the calls and imports between them. It keeps up with your snapshots, and it lights the range you pick, so you see where a change lands in the rest of your code.

## Open the Map

Select a project and click **Map**, next to **Changes** and **Lens** at the top right. The first time, ShadowGit draws the map of the newest snapshot ("Drawing the map…"). After that, the Map opens straight away on the map ShadowGit kept, and catches up from there.

The Map needs ShadowGit 0.3.9 or later.

## Read it

Three buttons arrange the map:

- **Areas**, the default, groups the code by folder.
- **Layers** groups it by where the code runs, or else by package or folder.
- **Change**, there while a range is lit, sets the changed code apart from the code that depends on it and from the rest of the project.

The card at the left names the project and the snapshot the map is drawn from, counts its symbols, areas, calls and processes, and lists its largest areas. Type in **Find a symbol or area** to find one on the map. Test files, and folders such as `fixtures` and `e2e`, stay off the map.

## Keeping up with your snapshots

When new snapshots land, **Newer snapshots: update** appears at the top. Clicking it draws the newest snapshot and moves the lit range up to it.

In a small project, where drawing the map takes under 3 seconds, the map redraws itself after each new snapshot while ShadowGit's window is open. Only the lit range waits for the click.

## Where a change lands

The Map lights the range picked in the **Range** menu on its left, the same range as the [Lens](/lens#pick-a-range). Pick **This AI session**, for example, or shift-click two snapshots. From the Lens, **Where it lands** opens the Map with its range lit.

The card's title becomes **Where it lands**. It counts the new and changed pieces and lists the areas the change lands in. Under **Dependencies**, it lists what the change makes depend on what, the same lines as the [Lens](/lens#dependencies). Under **Reaches**, it names the code outside the change that depends on code it altered.

The map draws each dependency between its two areas: a new one in green, a gone one dashed, and two areas that now depend on each other with a line each way. On a map drawn after the change that split or renamed one of the two areas, the line is listed on the card but not drawn.

| Dot | Means |
|---|---|
| Green | **New** |
| Orange | **Changed** |
| Orange ring | **Same code, runs elsewhere** or **Same code, exported differently** |
| Grey ring | **Comments only** or **Spacing only** |
| Red ring | **Removed** |

An area with a code change is outlined in orange, and one whose changes are only comments or spacing in grey. So a range that only rewords comments looks different at a glance from one that changes what the code does.

A range that changes no code says "Nothing in this range changes code: the map shows the whole project."

## Your assistant reads it too

Through the [ShadowGit MCP server](/installation), your AI assistant reads the same map: how the project is organised, and what depends on the code it's about to change. It looks before it edits, on its own, and you can ask it too (see [Your project's architecture](/installation#architecture)). Its answers come from the map you see here, and say how many snapshots behind the newest it is.

This needs ShadowGit 0.3.10 or later.

## Where the map is kept

ShadowGit draws the map on your computer and keeps it in its data folder (see [Where ShadowGit keeps its data](/installation#where-shadowgit-keeps-its-data)), under `maps`. It holds the names of your functions, classes and types and the paths of their files, and ShadowGit uploads none of it. What your assistant reads from it goes to your AI provider, like any file the assistant opens. Removing a project deletes its map.

## Troubleshooting

When the Map can't draw, it says "Couldn't draw the map" and why. It has the Lens's limits. A snapshot of more than 20,000 files or 64 MB of source code is too large, and drawing stops after 120 seconds. Leaving generated code and copied-in dependencies out with `.shadowgit-ignore` usually brings a project under them (see [Leave files out](/snapshots#leave-files-out)).

If lighting a range fails, the Map says "Couldn't light this range" and why.
